# 苹果外观品级标准与系统标签体系

> 本文档用于毕业设计：说明"国家标准 NY/T 439-2002《鲜苹果》"如何与本系统的
> 分级标签（特级/一级/二级/残次）衔接，以及**标签体系对模型的影响**。
> 更新日期：2026-07-31

---

## 1. 为什么引入分级标准

目前系统的分级完全依赖**缺陷面积占比**这一个维度（config.py 中
PREMIUM_THRESHOLD=0.05、STANDARD_THRESHOLD=0.15，即缺陷 <5% 特级、
5%~15% 一级、>15% 二级/残次）。这属于"自定义简化标准"。

答辩时最容易被问到的一个问题是：
**"你的特级/一级/二级划分依据是什么？"**
如果回答"自己定的"，说服力弱；如果回答"参照 NY/T 439-2002 鲜苹果等级规格，
并结合图像可测量指标做了简化"，就有了行业依据，属于规范化做法。

---

## 2. 标准等级体系（NY/T 439-2002 概要）

等级：**特等、一等、二等**（达不到二等的为等外果，即本系统的"残次果"）。

分级指标维度：

| 维度 | 说明 | 图像是否可测 |
|------|------|:---:|
| 果形 | 具有本品种固有特征形状，允许轻微不正 | 可测（圆度/凸包/宽高比，已有3维特征） |
| 色泽 | 按品种类型要求着色面积比例（红/黄/绿） | 可测（HSV 红色占比，已有特征） |
| 果面缺陷 | 碰压伤、刺伤、磨伤、日灼、药害、虫伤、裂果、锈斑等，每类有面积/数量限量 | 可测（缺陷 HSV 色域，已实现12维特征） |
| 果梗 | 完整 / 轻微损伤 / 缺失 | 部分可测（顶视/侧视拍摄时可见） |
| 横径（大小） | 大型/中型/小型果各有 mm 下限 | 不可测（需参照物/标尺，单图无尺度信息） |
| 成熟度/新鲜度 | 采收成熟度、无皱缩失水等 | 部分可测（颜色/光泽间接反映） |
| 洁净度 | 无尘土、无异常水分 | 部分可测 |

> 重要：上表为标准的维度结构归纳。论文中正式引用时，请以
> NY/T 439-2002 标准原文的具体数值为准（各品种类型的着色面积比例、
> 各类缺陷的面积限量、横径 mm 分级），可在知网/标准网下载原文核对。

## 3. 系统当前能"看到"什么

| 系统能力 | 对应标准维度 |
|----------|------------|
| 苹果分割（segment_apple，HSV 多色域） | 提取果面区域（果形、面积前提） |
| 缺陷检测（detect_defects，12 组 HSV 色域+阴影过滤） | 果面缺陷（碰压伤/腐烂/病变/斑点等可检出） |
| 170 维特征中的颜色矩/LAB/直方图 | 色泽、底色 |
| 170 维特征中的圆度/凸包比/宽高比 | 果形 |
| 170 维特征中的面积占比 | 果实大小（相对画面，非绝对 mm） |

结论：**系统的视觉能力覆盖标准的"果形、色泽、果面缺陷"三大维度**，
正好是标准里权重最高、也最容易被图像检验的部分。

## 4. 标签映射建议（论文可采用的方案）

### 方案一：直接换标签（严格对齐标准）
把数据集的每张图按标准三维规则人工标注为 特等/一等/二等/等外，
模型（SVM/RF/DL/YOLO）直接学习这四个等级。
- 优点：最规范、最像论文
- 缺点：必须重新标注全部数据 + 重训全部模型
- 缺点：横径等不可测维度会造成标签噪声（见第 5 节）

### 方案二：模型 + 规则引擎（推荐，改动最小）
模型任务**不变**（继续输出缺陷面积/等级倾向），另写一个"标准规则层"：

模型输出（缺陷面积占比、红色着色占比、果形圆度）
        ↓
规则引擎按 NY/T 439 阈值查表
        ↓
最终等级：特等 / 一等 / 二等 / 等外

- 优点：模型不用重训，标准作为后处理，可随时调整阈值
- 优点：就是桃子论文里"先验知识 + 模型融合"的思路，答辩好讲
- 优点：论文里可以同时展示"模型原始分级"与"标准规则分级"两列对比

### 方案三：混合（数据充足时做）
先按标准重新标注收集数据，模型学四分类；横径等不可测维度
用"像素面积 + 固定拍摄距离"近似（需在采集时固定机位并放置标尺）。

> 本系统当前结构最适合**方案二**：detect_defects 已输出缺陷面积，
> 特征里已有色泽/果形信息，只需新增一个 services/grade_rules.py
> 规则查表函数即可。

## 5. 苹果等级标准会对模型产生影响吗？（核心问题）

**会，但影响的是"标签（学习目标）"，不是算法本身。**

1. **标签 = 学习目标。** SVM/RF/DL/YOLO 学什么完全由标签决定。
   换标签体系 = 换学习目标 = **必须重训**，且准确率数字会变
   （通常先下降，因为四分类比二分类难、标签分布更不平衡）。

2. **不可测维度会造成"标签噪声"。** 如果标签里包含横径/果梗等
   相机拍不到的信息，模型"看不见"却要"猜中"，等于随机猜，
   直接把准确率拖低。这会让实验数据难看，且答辩时说不清。

3. **正确的打开方式：只采用图像可测维度。**
   用标准的"果形、色泽、果面缺陷"三大视觉维度定义标签，
   横径等维度单独说明"需要标尺/称重设备，本文简化处理"。
   这样模型没有额外负担，结果反而更可信、可辩护。

4. **对准确率的影响规律（可写进论文）**
   - 二分类（合格/不合格）→ 最容易，准确率最高
   - 三/四分类（特等/一等/二等/残次）→ 更难，准确率下降，但信息量更大
   - 类别不平衡（残次果远多于特等）→ 模型偏向多数类，需用
     class_weight=balanced（系统已用）或数据均衡
   - 这与论文里的桃子实验结论一致：4 类分级 SVM 只有 78%，
     而二分类缺陷识别可到 92%+。分级越细，准确率越低是正常现象，
     论文里应主动解释，而不是回避。

5. **结论**：标准不会"弄坏"模型；它只是重新定义了你要预测的目标。
   只要标签定义合理（只含视觉可测维度）、数据量足够、类别均衡，
   模型照样能学得很好。**建议按方案二（规则引擎）先行，数据充足后
   再升级为方案一（直接四分类），两个版本的结果正好可以做对比实验。**

## 6. 论文写作建议

- 在"实验方法"里写："参照农业行业标准 NY/T 439-2002《鲜苹果》的
  等级划分框架，结合图像可测量指标，将外观品级简化为
  特级/一级/二级/残次四级（或合格/不合格二分类）。"
- 在"讨论"里写："横径、果梗等指标依赖专用测量设备，本文方法基于
  单目视觉图像，故仅采用果形、色泽、果面缺陷三个视觉维度，
  相关指标可作为后续多传感器融合方向。"
- 若做方案二，可展示"模型分级 vs 标准规则分级"一致性（Kappa），
  这正好用上系统已有的 services/stats_service.py 里的 Kappa 函数。
