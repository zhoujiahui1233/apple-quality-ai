# 工业产线模式设计方案（Industrial Mode Design）

> 版本：V1.0　日期：2026-08-13
> 定位：智果·AI品控系统从「实验室单机版」走向「工业分拣产线」的架构设计与落地路径
> 关联实测数据：单张苹果检测平均 0.447 s（本机 CPU，含四模型融合），单相机理论产能约 8000 个/小时

## 1. 结论先行

- 算法不是瓶颈：0.447 s/张 已接近低速分拣线节拍需求；加速后可支持中速线。
- 真正的差距在**硬件触发、光源、机械执行、通信与稳定性**，不在模型本身。
- 建议：**做一个独立的「产线模式」软件层**（与实验室模式分开），先以「模拟产线」落地演示，
  同时预留光电触发/相机/PLC 真实接口；不主张现在直接对接真实 PLC（无产线硬件，无法验证）。
- 产线模式与实验室模式的关系：共享模型与数据库，但数据流、触发方式、界面、统计互相独立。

## 2. 实验室模式 vs 工业产线模式

| 维度 | 实验室模式（现状） | 工业产线模式（目标） |
| --- | --- | --- |
| 图像来源 | 手动上传 / USB 摄像头 | 工业相机（GigE/USB3 Vision），全局快门 |
| 触发方式 | 点击按钮 | 光电传感器 + PLC / 编码器触发，自动采集 |
| 光源 | 环境光 | 环形无影灯 / 条形光 + 频闪同步，遮光罩 |
| 检测对象 | 单张图片 | 每颗苹果多面（顶部+底部+侧面，按 ID 合并） |
| 结果去向 | 页面展示 + 存库 | 页面看板 + 分拣指令（喷阀/分级转盘）+ 存库 |
| 节拍 | 不限 | 按产线节拍（如 2~5 个/秒） |
| 稳定性 | 可容忍偶发失败 | 要求连续运行、自动重试、看门狗 |
| 数据流 | 同步请求-响应 | 队列缓冲 + 多线程流水线 |
| 统计 | 历史查询 | 实时看板：吞吐、漏检率、误检率、直通率 |
| 对接 | 无 | MES/ERP 数据上报（JSON API 预留） |

## 3. 工业模式软件架构（推荐）

```
[光电传感器] --触发信号--> [PLC / 采集卡]
        │
[相机A 顶面] [相机B 侧面] [相机C 底面]   ← 多相机，可扩展
        │           │           │
        └───────┬───┴───┬───────┘
                ▼
        [采集队列 Queue]（有界缓冲，防堆积）
                ▼
      [多线程推理池]（每相机一个 Worker，复用检测核心）
                ▼
      [按 AppleID 合并多面结果]（最差判定，防漏检）
                ▼
   ┌────────────┴────────────┐
   ▼                         ▼
[分拣指令输出]           [实时看板 + 数据库]
（喷阀/分级转盘，         （等级分布、缺陷占比、
 TCP/Modbus 接口预留）      节拍、漏检/误检统计）
```

关键设计点：
1. **触发链**：光电传感器检测到苹果 → PLC 输出脉冲 → 相机采集 → 图像入队。与界面完全解耦。
2. **队列缓冲**：有界队列（如 64 张），背压时降速提示，避免内存爆炸。
3. **多相机合并**：同一颗苹果的多个面用「苹果 ID + 时间窗」合并（刚做好的多角度融合逻辑直接复用）。
4. **分拣指令**：输出 `{apple_id, grade, action(ok/reject/grade_N), latency_ms}`，由执行端（模拟器/PLC）消费。
5. **看板**：每秒刷新：已检数量、当前节拍（个/时）、合格率、缺陷TOP类型、设备状态。
6. **稳定性**：推理失败自动重试 1 次；连续失败进入降级模式（只记录不判级）；看门狗重启采集线程。

## 4. 分阶段落地路径

### 阶段 A：产线模拟模式（纯软件，毕设可演示，推荐现在做）
- 新增页面 `/industrial`（产线看板）+ 模拟引擎：
  - 模拟传送带：固定节拍（可设 1/2/5/10 个/秒），定时触发
  - 模拟多相机：连续多张图作为「同一苹果的多面」自动合并
  - 模拟分拣：虚拟喷阀/分级通道，动画或日志输出
  - 实时统计：吞吐、合格率、误检率、直通率、缺陷 TOP
- 复用：现有检测核心（_apple_detect_core）、多角度融合（process_multi_upload）
- 产出：工业界面 + 架构验证 + 论文「产线模式设计」章节素材

### 阶段 B：真实相机接入（需硬件）
- 用 OpenCV 支持 USB3 相机 + 全局快门（工业相机 SDK 或 UVC）
- 添加相机标定：白平衡、曝光固定、ROI 裁剪
- 光电触发可用「软件触发」替代（GPIO 或定时），验证流水线

### 阶段 C：PLC / 执行机构对接（需产线）
- 预留接口：`POST /api/industrial/command`（分拣指令）、`POST /api/industrial/trigger`（触发信号）
- PLC 侧：Modbus TCP 从站 / 简单 TCP 协议，文档化
- 执行机构：喷气阀（多排）、分级转盘、机械臂

## 5. 算法加速路径（当前 0.447 s → 目标 <0.15 s）

| 手段 | 预期收益 | 说明 |
| --- | --- | --- |
| 输入裁剪 | 20~40% | 固定 ROI（传送带区域），跳过全图预处理 |
| 四模型并行推理 | 2~3× | 当前 SVM/RF/DL/YOLO 串行；改线程池并行后取 max 用时 |
| DL/YOLO 转 ONNX/TensorRT | 2~5×（GPU） | 桌面 GPU 或边缘盒子（Jetson）推理 |
| 简化融合 | 10~20% | 高置信样本只跑 DL+YOLO，低置信再补 SVM/RF |
| 批处理 | 10~30% | 多张图拼 batch 推理（YOLO 原生支持） |

## 6. 产线模式的统计口径（论文可写）

- 节拍（Throughput）：每分钟检测数
- 误检率（False Positive Rate）：合格品被判不合格 / 总合格品
- 漏检率（False Negative Rate）：缺陷品被判合格 / 总缺陷品（**产线最关注，多面融合直接降低此指标**）
- 直通率（First Pass Yield）：一次性判对的比例
- 每颗苹果检测时长 P95（保证不丢果的节拍上限）
- 抽检复核率：自动判「需复核」的比例（与现有 review 机制打通）

## 7. 现有系统可直接复用的部分

- 四模型检测核心：`services/detection_service.py::_apple_detect_core`
- 多角度融合判定：`process_multi_upload`（最差判定逻辑）
- 历史记录 / 复核队列 / 数据集积累：`DetectionRecord` + `dataset_collected/unlabeled`
- 模型版本管理 / 回滚：`/api/models/history`、`/api/models/rollback`
- 显著性分析：批次/品类对比（产线日报数据源）

## 8. 不建议现在做的部分（避免过度工程化）

- 真实 PLC 对接（无硬件，无法验证，留接口即可）
- MES/ERP 深度集成（留 JSON API 文档）
- 多产线负载均衡 / 边缘盒子集群（超出毕设范围）
- 相机 SDK 深度封装（先以 OpenCV 通用接口为主）
